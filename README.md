# 潮汐小岛

一个 Three.js 微信小游戏切片：采集漂流木/贝壳，建设菜园、小屋和码头，建筑会持续产出资源并自动存档。

场景使用 Blender 导出的 geometry-only GLB、烘焙 AO 顶点色和单张纹理图集。图集为各材质加入颗粒、木纹、泥灰、叶脉和水纹细节，优先加载 WebP、失败回退 PNG；棕榈、灌木、岩石和珊瑚使用 `InstancedMesh`。水面是程序化着色器，浪花沿不规则岸线动画。

植物采用已确认的柔和热带造型：分层饱满树冠、带厚度的下垂叶片、弯曲环纹树干和椰果；低矮灌木有独立杯形叶片、五瓣木槿花及花蕊。植物直接使用作者配色顶点色，避免图集把树干和花朵染绿；每种源模型合并为一个网格，并保留风动、树木生长及伐木交互。棕榈 6,372 三角面，灌木 4,950 三角面；移动真机帧率仍须单独验收。

仅替换植物、保留当前鱼类/珊瑚/岩石资源：`/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender_export_plants.py`。批准记录、源文件和运行截图在 `artifacts/plants-review/`；完整旧版生成器会生成旧植物，若运行它，需要再运行此植物替换命令。

沙滩采用不等宽的沙湾与沙岬、局部沙丘起伏、颗粒材质、潮湿沙斑和断续潮汐残留带，沙纹仅出现在局部下滩。`assets/coastline.json` 同时驱动 Blender 岸线、浪花着色器和鱼群/沙蟹边界，避免视觉岸线与可行走区域脱节。仅重建海岛（保留已有角色、植被与建筑资源）：`/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender_generate.py -- --island-only`。

海浪现在以约 5–7 秒的视觉周期冲上沙滩，再较慢退回：海面和沙滩共用冲刷相位，断续白沫贴合实际斜坡，并留下逐渐变浅的湿沙和薄水膜反光。台风与高潮增强冲刷范围；探索岛屿按较窄沙滩限制上岸距离。效果只改变材质，不改地形、碰撞、存档或生存时间，也不增加额外浪花网格。

人物与沙蟹在真实沙地上留下临时足迹：人物按距离交替留下左右鞋印，沙蟹留下交替四足的细点痕。足迹贴合沙坡，草地、码头、屋内及游泳/乘船不会留印，瞬移不会画连接线。冲刷使用与浪花相同的世界坐标相位和前缘，仅计算真正覆盖的浪潮；每次冲刷逐渐减弱，第三次后消除。上滩干燥足迹缓慢风化，固定 640 槽位、单次实例化绘制，并给人物单独保留槽位。仅视觉效果，不写入存档、不改变生存时间。

## 本地预览

```bash
npm install
npm test
npm run build
npm run preview
```

打开 <http://localhost:4173>。单指/鼠标拖动环岛，双指缩放，点击资源和金色圆台交互。

### 钓鱼操作

观察浮漂下沉后点击「提竿」（电脑也可用空格）。收线时拖动力度条可按百分比控制，绿色区域内都安全，不必精确对准单一点；左右按钮或键盘方向键每次微调 5%，轻收/稳收/快收按钮可快速设为 25%/50%/75%。鱼的动作每 2.6 秒切换，提前显示下一档提示，切换后留有 0.8 秒反应宽限。

不想频繁调力度时，点击「辅助：开」（电脑也可按 F）自动跟随推荐力度；手动拖动或微调会接管并关闭辅助。辅助只控制收线，仍需自己判断咬钩时机。

### 沙滩沙蟹

沙蟹使用独立的横向侧行逻辑，不再绕岛匀速转圈。每只会在自己的沙滩区域随机换方向、左右侧行、停顿，再继续行走；转向时先原地调整朝向，避开海水、草地和码头。八条两节步足分成两组交替抬起，步频跟随实际移动距离，停下后腿回到支撑姿态。身体顺着沙滩坡度倾斜，仍通过可见目标进行捕获，不增加自动奖励。

### 食物制作与菜谱

点击小屋旁的「海岛厨房」、底部「烹饪」或出海页的「烹饪与菜谱」。桌面一次展示八道带图片的菜谱；手机每页四道，制作、升级和进食按钮放大。选择菜谱可查看背包食材的现有/需求数量、等级、熟练度及升级后的饱腹值。

- 炭烤地瓜与香烤玉米默认学会；田园浓汤、果蔬沙拉、沙蟹玉米煲、香煎珊瑚鱼、鲜虾南瓜锅及银鲹田园拼盘可花 15–40 金永久解锁。
- 每道菜最高 Lv.3：累计制作 3 次加 15 金升级至 Lv.2，累计制作 8 次加 30 金升级至 Lv.3。饱腹补充值从 40–88 起，升级后最高达到 100。
- 制作需返回家园小屋旁，抵达厨房后经历 5 秒烹饪进度；已在屋内也可制作。完成时消耗真实背包食材，产出一份料理，不跳过游戏时间、不恢复体力、不赠送食材。仓库食材需要先取回；风灾中断或刷新未完成制作不会扣食材。
- 做好的料理保留制作时的等级与饱腹值，可存入仓库或携带远航。背包选择料理可逐份食用；烹饪页可快捷进食，远航补给优先吃料理。饱腹上限仍是 100，体力仍需吃饱、补水后休息恢复。

`cooking.test.mjs` 覆盖菜谱解锁、升级、原料不足时的原子性、容量、营养、鱼获统计、存档兼容和桌面/移动布局。

## 群岛远航（第一版）

家园不再是地图边界。点击小船或底部「航海」打开海图，选岛后走到码头登船出发。当前开放一片半径 125 米的连续海域，包含家园和四座可登陆岛屿：

| 岛屿 | 探索用途 |
| --- | --- |
| 泉眼岛 | 装满随身水壶，补充远航淡水 |
| 椰林岛 | 采集椰果作为储备食物 |
| 遗迹岛 | 搜寻仅可开启一次的金币宝箱 |
| 灯塔岛 | 收集菠萝种子，带回家园种植 |

- 电脑：W/↑ 前进，A/D 或左右箭头转向，S/↓ 减速；也可点击海面或在海图选择目的地。航线自动绕开陆地，键盘或触屏操舵可以接管。
- 手机/小游戏：按住航海面板的前进、转向按钮操船，松开后减速。靠近黄色浮标并减速后点击「靠岸下船」。岛上点击地面行走、点击可见资源采集。
- 点击「重新登船」或「航向家园」后，人物先走回登陆点。普通返航需要实际航行和靠岸；明确点击「救援返港」才会送回家园，费用最多 20 金，货物保留。
- 航海面板可喝水、吃饭。航行消耗少量体力，触礁扣船体耐久；船坏后只能缓慢应急航行或呼叫救援。吃饭补饱腹，仍须返家休息才能恢复体力。
- 航行不跳过游戏时间，后台不推进。岛屿发现、登陆、采集冷却和船/人物位置自动存档，刷新可继续远航。普通资源一天后补充，遗迹宝箱不重复发奖。

这是有限群岛海域的可玩基础版，不是无限地图；当前远岛主要提供步行采集和探索点，深海鱼类捕捞仍使用原有出海机制。浏览器已验证登船、航行、泉眼采集、刷新恢复和返港；微信端仍需开发者工具与真机验收。

### 群岛美术细化

远岛使用有起伏的不规则地形，草地、干沙、湿沙和水下礁盘连续过渡；人物脚下与地形共用高度函数，保留原有登陆点和航行碰撞范围。四岛分别加入流水泉池、编织椰果篮、石拱遗迹与圆顶宝箱、带灯室和栏杆的灯塔，登陆区有木栈台、绳环和标识。木材与石材有程序化表面细节，浅水礁石、珊瑚、海草和装饰鱼群复用主岛资产；装饰鱼不提供凭空捕获奖励。

海浪按各岛实际岸线生成，水面随日照变化并有连续反光，远处资源文字自动隐藏。美术几何预算、登陆高度、船只安全间距及鱼群不穿沙滩由 `voyage-art.test.mjs` 检查；构建通过不代表本轮已完成浏览器画面或手机真机帧率验收。

### 昼夜与台风天气

日照随游戏时间连续变化，傍晚变为暖色低角度光，18:00 后日光归零；夜晚仅有较弱的冷色月光及月光散射，海面同步变暗并保留月光反射，不再保留白天环境光。台风准备期出现风雨，登陆期为密集斜向暴雨，云层遮暗日月光，地面和水面有雨滴涟漪。雨场随航海视角移动并循环更新，长时间运行不会飘出画面；小屋内部遮蔽雨滴。

`environment.test.mjs` 检查连续光照、夜间无日光、云层遮挡、雨场长期运行与室内遮雨。独立渲染预览复用真实 GLB 和生产海水材质，不读取或修改存档：先构建，再运行 `node tools/environment-preview.mjs`，访问 `/environment-preview.html` 切换时间和天气；此页不包含在默认发布构建中。浏览器验证截图在 `artifacts/environment/`，微信端性能仍需真机验证。

## Cloudflare Pages 部署

- 生产分支：`main`
- 构建命令：`npm run build`
- 输出目录：`dist/web`
- 自定义域名：<https://island.dailysnake.com>

Cloudflare Pages 连接 GitHub 仓库后，推送到 `main` 会自动触发生产部署。

### Google 登录

构建时通过 `GOOGLE_CLIENT_ID` 注入 Google Identity Services 的 Web 客户端 ID：

```bash
GOOGLE_CLIENT_ID="your-client-id.apps.googleusercontent.com" npm run build
```

Cloudflare Pages 中应在生产环境变量里设置同名变量，并在 Google Cloud OAuth 客户端中把 `https://island.dailysnake.com` 配置为授权 JavaScript 来源。服务器也需要同名运行时变量，以校验 Google ID token 的签名、来源、有效期和用户 ID。登录凭证只暂存在标签页，不保存在存档数据库。

### 云存档

账号菜单提供手动上传、下载、进度冲突选择和历史恢复。D1 保留最近 30 个版本；恢复会写入新版本。下载或恢复前本机保留 5 份备份，可在历史恢复中选择。网络失败不会清除本地存档；账号和游客的本地进度分别保存。切换账号后须选择此账号本地或云端进度，不能把其他账号存档直接上传。载入不会推进游戏时间，也不合并资源。

生产配置步骤（已有 Pages 项目仍由 dashboard 管理，不要使用本地配置覆盖生产）：

1. 在现有 Cloudflare 账号中创建 D1 数据库 `island-saves`。
2. 在数据库控制台执行 `migrations/0001_cloud_saves.sql`（或通过 Wrangler 对该数据库执行迁移）。
3. 在现有 Pages 项目的生产环境新增 D1 binding，变量名为 `SAVES_DB`，选择该数据库；配置运行时 `GOOGLE_CLIENT_ID`。
4. 重新部署。仓库根目录的 `functions/api/` 会自动构建 `/api/account` 和 `/api/saves`。
5. 使用两个独立设备/浏览器登录同一账号，验证上传、冲突选择、下载和恢复；未绑定数据库时接口返回 503 并保留本机进度。预览环境应使用独立测试数据库，不能绑定生产数据库。

本地完整服务：在未跟踪的 `.dev.vars` 设置测试用 `GOOGLE_CLIENT_ID`，构建时注入同一个 ID，执行 `npm run db:local` 后执行 `npm run dev:cloud`。Google 测试客户端需要授权 `http://localhost:8788`。普通静态预览只用于场景检查，无法处理存档 API。`wrangler.toml` 未设置 `pages_build_output_dir`，仅用于本地，不接管现有生产配置。

`npm test` 包括签名校验和真实本地 D1 测试，覆盖两台设备并发写入、恢复时冲突、历史保留、重试幂等、账号隔离、断网和时间保持。测试身份只由测试代码注入，生产接口没有测试登录或身份绕过开关。

## 重新生成美术资产

人物是原创的圆润海岛居民：约 2.7 头身、大眼睛与腮红、短肢体、草帽和小背包。GLB 保留头部、双眼和四肢独立关节，支持眨眼、轻微转头以及原有工作/游泳动作；工具握点挂在右手关节下。保持原有世界高度，导出三角面预算不超过 8,000，手机真机帧率仍需单独验收。

重新生成角色与正面、侧面、背面预览（预览和 Blender 源文件在 `artifacts/avatar/`）：

```bash
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender_generate_avatar.py -- --review
```

图集由 `tools/build_atlas.py` 生成（只需 Pillow，不依赖 Blender）：

```bash
python3 tools/build_atlas.py
```

GLB 几何仍由 Blender 导出（需要可用的 Metal/GPU 后端）：

```bash
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender_generate.py
```

## 验收边界

- 已实现：共用 Three.js 场景、Blender GLB 海岛/建筑、AO 图集、实例化植被、程序化水面、采集建造循环、浏览器与微信构建产物。
- `npm test` / `npm run build` 只证明逻辑和打包，不等于微信运行通过。
- 开发者工具预览、真机帧率/发热/内存、上传和发布必须分别验收。

KTX2 暂未接入微信端：Three.js 的 KTX2 解码器依赖浏览器 Blob Worker，需先做微信 Worker/WASM 适配并完成真机验证。SSR、SSAO、Bloom 和物理系统仍未加入。
